💰 演者への支払いフロー
演者への動画単価の支払いを、毎月どう締めて、どう本数を伝えるか。
集計は投稿計画表の中で完結します。このページは手順の説明で、実際の数字はスプレッドシートにあります。
3行でいうと
① 動画1本あたりの単価で毎月払う。実写収録とAI音声収録で単価が違う
② 締めは月末。「何月分か」は稼働日（実写＝撮影日／AI音声＝AI生成日）で決める。公開日ではない
③ 投稿計画表の 請求集計 タブで年と月を入れると、本数と金額が自動で出る
1. 単価
演者収録方法1本あたり
あさひ実写収録2,000円
りい実写収録2,500円
あさひAI音声収録1,000円
りいAI音声収録1,000円

対象は あさひさん・りいさんの2名です。キアラさんは今のところ対象外です。

単価を変えるときは、投稿計画表の 単価マスタ タブだけを直します。 数式には金額を直接書いていないので、そこ1か所で全部に効きます。

⚠ AI音声の1,000円は「声を使った演者にだけ」払います。両演者ではありません。
1本あたりの支出は 1,000円 です。一度「両演者に払う」という説明がありましたが、確認して否定されています。 両演者だと支出が倍になるので、ここを取り違えないでください。

AI音声収録について（2026-08 開始）

演者は収録に関与しません。AI音声で作った動画は、演者が撮影していません。

そのため AI生成を行うたびに本数を数えて、その分を伝えるという業務が新しく発生します。 実写のぶんとは分けて伝えてください（単価が違うため）。

2. 毎月の手順
  1. 稼働日を埋める。投稿計画表の 動画アーカイブ タブで、その月に稼働した動画の行に 収録方法（実写／AI音声）と 稼働日 を入れる
  2. 請求集計 タブを開いて、年と月を入れる。本数と金額が自動で出ます
  3. いちばん下の「見張り」2つが 0 かを確認する（下の §4）。0 でなければ請求から抜けている本数があります
  4. 演者ごとの本数を伝える。実写とAI音声は単価が違うので、分けて伝えます

触るのは年・月・稼働日・収録方法・単価だけです。ほかは数式なので触らないでください。

⚠ 稼働日が空の行は、どの月にも集計されません。入れ忘れると、その本数が請求から静かに抜けます。
⚠ 稼働日は「日付」として入れてください。文字列で入れると日付の比較が一致せず、 本数が黙って 0 になります（エラーは出ません）。0本で出たら、まずここを疑ってください。
3. スプレッドシートの作り

動画アーカイブ タブに足した2列

列値なぜ要るか
収録方法（J列）実写 ／ AI音声単価がこれで変わるため
稼働日（K列）日付締めの基準。実写＝撮影日、AI音声＝AI生成日

fetch.py は列を名前で探しているので、列を足したり並べ替えても壊れません。 逆に列名を変えると黙って空になります（エラーは出ません）。

★ ナレーター欄に「AIあさひ」を作らないでください。
ナレーター 列は、そのままダッシュボードのナレーター別集計に使われています （りい194本／あさひ77本ほか）。ここに AIあさひ を足すと、 あさひが2系列に割れて、過去との比較が切れます。
もう1つ、この列の入力規則はバウンドスクリプトが1時間おきに貼り直しています。 シート側で選択肢を足しても、数時間後に静かに戻ります。
収録方法は別の列で分けてください。ナレーターには声の主をそのまま入れます。
おまけ：この分け方だと、「AI音声の動画は実写と比べて伸びるか」も測れるようになります。 ナレーター欄に混ぜてしまうと、この比較ができません。

足した2つのタブ

タブ中身
単価マスタ演者／収録方法／単価。金額を書くのはここだけ
請求集計年と月を入れると、演者ごとの本数と金額が出る

名前付き範囲（数式はこれを使っています）

数式の中に日本語のシート名を書かずに済むよう、6つの名前付き範囲を作ってあります。 消すと請求集計が全部エラーになります。

名前範囲
narrator動画アーカイブ の ナレーター列
method動画アーカイブ の 収録方法列
workdate動画アーカイブ の 稼働日列
mPerson / mMethod / mRate単価マスタ の 演者／収録方法／単価

本数は COUNTIFS、単価は SUMIFS で引いています。特別な関数は使っていません。

4. 月末に必ず見る「見張り」2つ

請求集計 タブのいちばん下に、黙って請求から抜けるのを防ぐ数字が2つあります。 どちらも 0 であることを確認してから締めてください。

見張り0 でないときの意味
稼働日が空の行 その本数はどの月にも集計されていません。請求から抜けます
単価マスタに無い演者 あさひさん・りいさん以外に稼働が入っています。単価マスタに足すか、入力ミスかを確認

キアラさんを単価マスタに入れていないのは、この見張りがあるからです。 対象外の人に稼働が入っても、0 でなくなるので気づけます。

5. 決まったこと・未決

決まったこと（2026-08-25）

AI音声の1,000円は声を使った演者にだけ両演者ではない。1本あたりの支出は1,000円
対象は あさひ・りい の2名キアラは今は作らない
対象は 2026-08 分から過去にさかのぼらない
1本＝実写かAI音声のどちらか一方混ざることはない
単価は単価マスタで変える数式には直接書かない
★ 未決が1つ残っています：締めたあとに金額を固定するか
いまの形だと、締めたあとに稼働記録を編集すると過去月の金額も変わります。 つまり「先月いくら払ったか」が後から動きます。支払い履歴としては、これでは足りません。
やり方は2つあります。どちらも入れていません。
・確定額を別タブに書き出して固定する（締めた月の行をコピーして値で貼る）
・支払い済みフラグ列を持つ（2026-08 締め済み など）。締めた行は編集しない運用にする
